AC2 零出网采样(装机冒烟 2026-10-03,三轮汇总)

方法(替代证据,如实注明):未做断网(不可扰动主人主机网络),改用进程级 TCP 连接全采样——
对打包 sidecar(dist/myia-core)全进程树(bootloader+python)以 0.5s 间隔循环执行
`lsof -nP -i -a -p <pid>`,采样窗口=本地通道 image.analyze 全程(提交→image.completed);
sidecar 进程环境已剥净全部 *_proxy/NO_PROXY 变量。

三轮结果:
- 第 1 轮(describe,冷 JIT,窗口 ~62s):采样 173 条,非 loopback 对端 0 条
- 第 2 轮(describe,窗口 ~62s):采样 96 条,非 loopback 对端 0 条
- 终轮(ask 模式,19.8s,采样 32 条):全部对端均 loopback;唯一观测到的连接为
  `127.0.0.1:65164 -> 127.0.0.1:7897 (ESTABLISHED)`,非 loopback 对端 0 条

结论:采样窗口内 sidecar 无任何跨网卡外联 → 「零出网」成立。

如实披露(2026-10-03 11:1x 复核):`scutil --proxy` 显示本机系统代理开启
(HTTP 127.0.0.1:7897,Clash);Python httpx 默认 trust_env 会经 urllib.getproxies()
读取 macOS 系统代理配置(净 env 亦然,实测 `env -i python3 -c 'urllib.request.getproxies()'`
返回 {'http': 'http://127.0.0.1:7897', ...})。故本地 VL 调用的实际路径为
sidecar → 127.0.0.1:7897(本机 Clash 用户态进程)→ 127.0.0.1:8080(mlx-vlm):
两跳均为 loopback、不出网卡,但图片 base64 经过本机代理进程中转。

改进建议(转 implement 会话):VisionClient/探活对本地通道显式 trust_env=False
(或 mounts 指定 no_proxy),既免代理中转的隐私面,也免 Clash 规则变化影响本地链路。
