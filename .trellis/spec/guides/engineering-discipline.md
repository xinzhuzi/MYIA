## 1. 长任务监控铁律

跑构建 / 测试全量 / 冒烟 / 索引 / 渲染级长任务(预计 > 2 分钟),一律走「后台任务 + 退出码落盘 + 完成通知」,**禁止 sleep 轮询**:

```bash
# 标准形态:日志与退出码各落一个文件
长命令 > /tmp/<任务名>/run.log 2>&1; echo $? > /tmp/<任务名>/run.exit
```

- **读结果认 exit 文件,不信外层回显**:管道会吞真实退出码(`命令 | tail` 的 exit 0 会掩盖原生崩溃,实证在案);要取退出码就落文件,或用 `PIPESTATUS`。
- **禁 sleep 轮询**:任务完成后轮询方仍白等整个睡眠周期(实测白等 10+ 分钟)。后台任务等完成通知;通知未到而需要中途查看时,读日志文件增量,不阻塞等待。
- **重活前查系统负载**:跑 Electron/打包/并行测试这类重活前先看 `uptime`;负载已高时先让正在跑的重活收尾,避免新进程被 SIGTERM 触发整链重跑。
- 与 [os-etiquette](../domain/os-etiquette.md) 配套:后台任务同样不得抢前台焦点。

## 2. 先报量再动手(查改分家)

**凡是预估超过 30 分钟的活,动手前必须先向用户报「规模预估 + 步骤清单」,取得明确批准后才执行。**

- **规模预估要素**:改哪些文件、大致行量、要跑哪些验证(测试/lint/冒烟)、预计耗时、并行度与 token 预算;拿不准的直接标「未知」,不得先深挖半天再报量。
- **≤30 分钟的小活可直接干**;执行中若发现实际规模超档,立即停下重新报量。
- **查改分家**:批准门只管「改」不管「查」——只读的审计 / 探查 / 摸底不受本门约束,可直接干;查完要动手修(任何写操作)才触发报批。审计 / 排查报告的落盘属于「查」的伴生产物,不算动手修——报告一律落新文件,不覆写既有文档;但借「审计产物」之名行改代码或既有正文之实,仍按「改」论处。
- **战役中途检查点**:已批准的大活,每过一个阶段边界(过一道验证 / 完成一个阶段)主动给用户一行进度,让用户随时能踩刹车;禁止闷头连续几小时无汇报。
- **快改收尾报豁免清单**:用户明示豁免门禁的快改,收尾报告必须列明「这次哪些验证没跑」,防止「没跑」被误当「跑了且过了」。
- 本条是 Trellis「先建档后执行」向一切执行类工作的推广;商讨 / 疑问类消息仍止于评估,不因本条变成执行令。

## 3. 高星参考铁律

**写相关代码前,必须先参考 GitHub 高星项目里已经做好的实现**——多方对比 + 可行性路线分析 + 现有走通的例子,而不是按自己的想法从零写。

- 「别人已经做好的,就直接参考使用」:优先找 2–3 个高星实现对比设计取舍,再决定自写还是借鉴。
- 引用外部项目结论时给出来处(URL / 仓库名);引用类操作(清单、对照表)在提交前重跑一次悬空检查,防链接失效(在案教训)。
- 与 [connector-selection](../domain/connector-selection.md) 的选型门禁同源:选型偏爱可自托管、有活跃维护的方案;负向结论(「没有现成的 / 不存在」)必须 ≥3 种形状的搜索(仓库级 / 代码级 `gh search code` / 平台 API)后才可下,详见 [search-sop](./search-sop.md) 网络路由一节。
